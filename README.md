# The Fourth Frequency / 第四频段

《第四频段》是一个面向 Minecraft 1.21.11 的 Fabric 生存恐怖叙事模组。玩家从唯一的零号站醒来，借助一台会提供真实生存信息的旧终端前进，并逐渐发现：信任本身就是施工。

## 当前状态

当前开发版为 `0.4.0-beta`。生存主线、四页终端、五阶段共 19 项异象、五形态个人校正者追逐、对应维度私人镜像、“第四频段·世界接口”末地终局、原版终末之诗回程和 Windows Meta 演出均已实现。

当前数据与协议基线：

| 领域 | 当前版本 |
|---|---:|
| 世界/终端持久化 | schema v10 |
| 终端主快照 | v11 |
| 工具快照 | v6 |
| 导航载荷 | v6 |
| 异象生命周期 | v3 |
| Debug 状态 | v5 |
| 世界接口状态/协议 | format v1 / protocol v1 |

旧的四阶段“异象主体”末地战、热栏错位终局和主世界旧祭坛已从现行运行时与测试中删除；旧祭坛、旧设施和旧实体存档不再保证兼容。当前终局只使用世界接口流程。

## 运行环境

| 组件 | 版本 |
|---|---|
| Minecraft | 1.21.11 |
| Fabric Loader | 0.19.3 或更高的兼容版本 |
| Fabric API | 0.141.4+1.21.11 |
| Java | 21 |

客户端和服务器都需要安装本模组与 Fabric API。模组许可证为 [All Rights Reserved](LICENSE)。

## 安装与构建

1. 取得 `build/libs/thefourthfrequency-0.4.0-beta.jar`。
2. 将该 JAR 与对应版本的 Fabric API 放入客户端和服务器的 `mods` 目录。
3. 使用 Java 21 启动 Fabric 1.21.11，创建新世界或连入服务器。

从源码构建：

```powershell
.\gradlew.bat clean build --no-daemon
```

发布 JAR 输出到 `build/libs/`；更多命令见 [测试策略](docs/testing.md)。

## 主线与终端

首次进入世界后，零号站会按固定 Tick 预算建造。它先在原始出生点附近挑一块平整、不临水的地面落址，再自下而上补齐地基、地板、墙体和屋顶，所以站体不会悬空、不会半截埋在山坡里，也不会有树干穿过屋顶。玩家在站心的铜格栅上醒来，正面朝向北侧的设备墙：熔炉、工作台、两格空着的终端架、一张没有书的讲台和一只空木桶。站体自带照明，室内与屋顶都不会刷出敌对生物；东侧一角已经塌了，屋顶开着口，只剩铜栅挡住墙上的裂口。这里没有战利品。

每位玩家只会获得一台有效的个人终端。手持终端右键打开私人界面，界面不暂停游戏，也不会把正文写入聊天。

- `HOME`：显示当前服务端权威生存目标、渐进式工具建议和最近记录。
- `TOOLS`：提供住处、矿物、传送门、天气、导航和要塞六个工具；未解锁项可查看条件，但服务端会拒绝越权动作。
- `RECORDS`：聚合剧情、里程碑、文件调查与追逐预警记录；19 种普通异象不会写入该页。进入页面即统一标记为已读。
- `FILES`：顶部标签会在收到新文件时显示未读提示，进入该页即清除提示；这不会代替四份破损文件各自的阅读记录。每份破损文件暴露真实标题，但固定遮住 2—3 个字，正文保留约一半、分散在乱码间的可读片段并标注已尝试还原；完整日记从终端创建起常驻并以乱码标题锁定，四份破损文件全部读完后才自动解锁。目录共保留 7 类文件；真实跨维度往返改写 `RECORDS` 与完整日记末行，不再增加重复文件。
- 数字键 `1`–`4`：切换页面；`Esc`：关闭终端。

终端的双针指南针中，红针始终指北，另一根针指向当前选定的具体矿物方块或结构。矿物由“探测”触发，它不再掷骰决定矿种，而是报告探测点周围真实存在、且最稀有的那一种：矿越稀有听程越短（煤 32、铁 28、金 20、钻石 16 格），所以站在森林地表反复按不会听见钻石。探测消耗一次充能，最多存 3 次、每 3 分钟回复 1 次，没有随机失败；范围内确实没有东西时读数就是“范围内无读数”。读数在 12 格以内锁定到具体方块并提供导航按钮，更远只给出量化方位与 ±25% 的距离区间，锚定在按下按钮的采样点上，不会变成路径点。矿种按主线逐级开放：砍木头后开放煤与铁，交足铁后开放金，进入下界后开放钻石与绿宝石。跨维度后读数作废。终端关闭时还会自动勘测 5 格内的矿物，但只针对钻石与绿宝石这两种值得停下来的矿：探到即报，没有概率判定，读数直接落成可导航的精确目标。它不再随玩家走出 5 格就消失——与探测读数一样，只在矿被挖空、跨维度或走到目标处时才失效。进入矿物目标三维 1 格范围后，导航自动结束并清除当前目标，同时在物品栏上方提示。传送门工具只接受主世界与下界之间的往返：进入下界时记录下界侧到达点，返回主世界时记录主世界侧到达点，以最后一次往返为准，页面只提供导航按钮；追逐、末地和其他维度变化不会覆盖该记录。要塞工具在成功获得 3 颗末影之眼后开放，完整估算与导航仍要求 3 次真实投掷记录。结构候选按当前维度显示、最多三项，末地不提供候选；下界会立即提供地狱堡垒。到达半径按结构大小区分（村庄 48、下界要塞与堡垒遗迹 40、废弃矿井与试炼密室 28、废弃传送门 20 格，均为水平距离——原版把结构定位点的高度固定报成 0，竖直方向没有可比的信息）；进入该范围后导航自动结束、在物品栏上方提示并从候选中移除，终端保留一次相对方向提示。住所与传送门工具在走到目标 6 格内时自动结束引导，要塞工具则在记录到“已找到要塞”时结束。到达支线信号地点后，近场接收器会直接进入可调频状态，不要求先打开导航工具。

当前任务从“认识终端”开始：依次点击顶部四个标签后完成。后续顺序为：收集 12 份任意原木/木板 → 收集 6 份铁样本 → 进入下界 → 收集 8 根烈焰棒 → 返回主世界 → 制作 4 只末影之眼 → 记录 3 次真实投掷 → 找到要塞 → 进入末地 → 阻止世界接口。每张任务卡右上角显示奖励；任务完成后立即推进，奖励直接进入背包，空间不足时掉落在玩家脚边。正常主线不需要命令，也不以设置重生点或建造住所作为推进条件。

## 异象与个人追逐

异象目录共 19 项，采用五阶段滑动池；其中环境静默、时相偏移与计量偏移是持续数分钟的低强度“持续型”异象，用来填住短事件之间的空白。主线只提高最高阶段；实际阶段每次最多上升一级，并要求在当前阶段累计至少 20 分钟合格在线时间及完成 2 次异象；当实际阶段落后主线上限两级及以上时，曝光要求减半（10 分钟）以便追赶。首次异象在绑定后 4–7 分钟安排，常规间隔从阶段 1 的 8–14 分钟逐步收紧到阶段 5 的 5–9 分钟；最近三次不重复，新阶段内容使用三倍权重，强接口异象另有 20–30 分钟冷却。首次进入下界与首次投掷末影之眼会安排一次“签名异象”：约 30 秒内把下一次异象提前，并按主线上限优先选择未见过的高阶内容；若当次触发失败，签名会保留到下一次成功触发。

校正者拥有寻声者、定向者、截断者、越界者和接口校正者五个个人形态。挖矿、探索、战利品、建造和交易都能提供第一形态活动证明，不要求玩家先建家或必须通过采矿获得铁。每个形态都先经异象完成安全演示；正式与测试入口随后都从 10 秒终端预警开始，依次经历终端震动、渐进掉帧、2 秒卡死和黑屏隐藏加载，再进入 60–110 秒正式追逐。成功追逐之间间隔 20–30 分钟，快速推进主线不会产生连续补追。

正式追逐发生在当前维度类型对应的私人校正层。入场时复制玩家周围 5×5 区块和上下各 48 格，之后按玩家所在区块持续流式扩展；水平方向没有固定 30 格限制。追逐画面使用黑白低清滤镜并全程施加无粒子夜视，底部只常驻“尝试逃离”，其他提示延后到追逐完全结束；校正者在玩家周围 25–42 格的完整圆环上生成，不再限制在视线后方——只会出现在背后的东西可以靠转身推理掉。坚守者心跳在校正者所处坐标播放，因而自带方位与距离衰减；它会快速破障、拆除高台支撑和垂直追击，在检测到玩家身处矿洞时则动态减速。玩家既可撑过时限，也可持续拉开距离、切断视线或直接击杀校正者。捕获会在 3 秒卡死与故障音后扣除一颗心生命上限，但生命上限降至 6 颗心及以下后捕获不再继续扣除；逃离会显示 3 秒绿色结算并增加一颗心生命上限，两种结果都以黑屏隐藏返回原维度。镜像挖掘不产出资源，简单放置物由持久账本在结束后退款。追逐正式开始的瞬间，源维度 64 格内其他已绑定终端会记录一行“附近一台终端的信号暂时无法解析”，不透露追逐内容。不同玩家的追逐、形态、实体和地形互相隔离，全服同时最多两场。追逐结束后玩家回到自己在镜像里所站位置对应的源世界坐标，而不是被拉回出发点。

异象目录之外还有两类常驻演出，它们不占异象槽位、不写异象历史，也不算在 19 项里：**观察者**只在终端波段尚未推进的故事开头出现，且必须是夜间或地下，18–32 格外站着，躯干偏开而头已转回来；**HIM** 只出现在玩家还没看过的方向上（偏离视线 95°–180°、22–44 格），站上几十秒就消失，同一时刻全场只有一个。完整规则见 [异象、终端形态与个人追逐](docs/anomalies-and-pursuits.md)。

## 末地终局：世界接口

亲身经历过至少一场个人追逐后，最后一颗末影之眼才会为当前存档准备末地主岛上的终局。被捕获同样计入这一条件——捕获已经扣除一颗心的生命上限，不再额外阻挡终局；能否推进校正者形态仍然只看成功次数。正式战场使用原生主岛表面，不生成承载整场战斗的额外平台；只贴合地表布置 11×11 共振祭坛、20 座惰性折跃门与 10 个权威稳定锚。

仪式会冻结 1–8 名当前在线非旁观者名单；每个人都必须**手持**自己的有效绑定终端右键共振核心，亲手把它插进祭坛——空手右键只会打开界面查看名单与进度。完整提交前可撤回或中止，名单变化也会回滚并返还已托管终端；全员提交后事务原子生效，战斗开始。

- BOSS 最大生命为 `600 × 冻结人数`，分为“监听胚体 / 吞频构装 / 世界接口”三个只前进不后退的形态，生命阈值为 70% 和 35%。
- 世界崩坏计时为 7200 Tick（6 分钟）；只要任一冻结成员在线就会继续，全员离线时暂停。战斗阶段的最后 10 秒，客户端 HUD 以红色脉冲、放大秒数和逐秒递紧的终端音强化倒计时，使同 Tick 临界裁定在情感上可归因。
- 稳定锚会持续治疗目标（每座每秒 0.025% 最大生命），但同时使其更慢、攻击间隔更长且承受完整伤害。拆锚停掉对应份额的自愈，代价是接口更快、出招更密，且承受的伤害每拆一座下降 5 个百分点（全拆后为 50%）。拆锚不再消耗崩坏计时——那条代价把整场战斗的核心动作变成了净亏损；系数的每一次变化改由 HUD 血条上拂过的一层金光即时报告。目标不会自行摧毁稳定锚。整场战斗中第一次对锚的有效攻击会被吸收，并向全体成员广播终端警告说明拆除是不可逆的取舍；此后的攻击才会真正摧毁锚。
- 八类权威攻击依阶段解锁：追踪式激光扫射、高速龙息弹、天降光束、武器扣押（原槽位留下「已被暂时禁用」的屏障占位）、抓取抛天、热栏公开投放、触手抽击与强制驱逐。除强制驱逐外每种攻击都有 2–4.5 秒的锁定窗口，被锁定玩家会同时收到全屏预警、脚下粒子环与音效，锁定期内不造成伤害；激光的追踪延迟与光束的蓄力时长都必须大于各自的命中半径所需的位移，规避才是真的成立。被扣押的武器与玩家控制状态有持久恢复账本。
- 永久末地伤痕受 8192 格整场预算、每 Tick 32 格上限、中央 160 格范围与出口 8 格安全半径约束；基岩、黑曜石柱、传送门、方块实体、关键 MOD 方块和 `#thefourthfrequency:world_interface_immune` 均受保护。

倒计时到达 100% 的同一 Tick 先裁定失败；只有在此之前造成致命伤害才是成功。战斗后原生主岛祭坛开启 3×3 出口，玩家进入后使用真实原版 `WinScreen` 和 `PERFORM_RESPAWN` 回程，仅按成功/失败与当前语言替换该次终末之诗，并把诗后的制作人员名单替换为本模组自己的名单（`credits_zh_cn.json` / `credits_en_us.json`）。未经过世界接口终局的原版结算不受影响。

## 结局、F8 与存档

成功和失败都会写入本地结局锁。之后返回主菜单时，单人、多人和 Realms 三个游戏入口会禁用，设置与退出等其他按钮仍可用。

失败演出会替换桌面壁纸并打开一份由 MOD 写入的记事本，正文直接告诉玩家“重新启动游戏，按下F8来撤销MOD对电脑造成的所有更改”。该窗口按普通尺寸打开而非最大化。若检测到 Wallpaper Engine 正在运行，会先暂停其播放（`-control stop`）使壁纸可见，F8 恢复时再恢复播放（`-control play`）；MOD 不会结束该进程。

`F8` 不是随时可用的 Meta 开关。只有已记录结局时，按下 `F8` 才会打开完整重置确认；确认后会恢复 MOD 拥有的桌面、Notepad、窗口和资源包演出，重置客户端演出标记并正常关闭游戏。重启后，本次结局的本地单人存档会以 MOD 自有无损隔离标记显示为“存档已损坏”并禁止进入；它不会破坏 `level.dat`、区域或玩家数据。重新体验需创建新世界。

如客户端在结局事务中断，可在 JVM 参数中加入 `-Dthefourthfrequency.safeMode=true` 启动安全恢复。

两种结局都不再由 MOD 关闭游戏或断开连接。原版回程把玩家送回主世界后，客户端保持运行，屏幕下方以 actionbar 反复提示“游戏流程已结束，请返回主菜单”（每 2 秒一次，持续 60 秒），退出交还给玩家自己的暂停菜单。失败结局另外把方块、实体和流体渲染为缺失材质——这原本只给已开放 LAN 的房主，现在对所有失败者一致；服务器世界与 LAN 客人仍不受影响。

之所以取消自动关闭：由 MOD 驱动 Minecraft 的关闭流程在这个终局并不可靠。终局刚从世界里挖掉了数千个方块，客户端会卡在存档过程里，最终被 `Client shutdown watchdog` 判定超时并杀掉进程，停在“保存世界中”。现在只有确认过的 F8 重玩重置仍会关闭客户端，且是在主菜单、没有世界加载时执行的普通退出路径。

## 客户端演出与视距

第一次到达标题页时会显示 v3 安全告示，说明演出范围、设备安全、存档不可逆后果和 F8 的真实用途。确认版本单独保存在 `config/thefourthfrequency-safety-notice.version`。

客户端第一次进入世界会播放一次 Alpha 加载崩坏，之后使用持久的 Programmer Art → Golden Days Base → Golden Days Alpha 资源顺序、旧版加载界面和 `Minecraft Alpha 1.0.0` 本地演出身份。

世界侵蚀仅作用于游戏内纹理，不会退出全屏、最大化或以其他方式重排游戏窗口。

成功终局返回主世界之前，客户端视距按维度强制锁定为主世界 6、下界 12、末地 16、其他维度 12，设置控件不可调整，雾边界同步使用对应值。仅成功诗篇完成且玩家真正返回主世界后，视距设为 16 并持久解锁；失败不解锁。

## 配置与调试

首次启动生成 `config/thefourthfrequency.json`。

| 配置项 | 默认值 | 作用 |
|---|---:|---|
| `meta.enabled` | `true` | 允许固定白名单的本地 Meta 演出 |
| `meta.peakVolume` | `0.8` | 本模组音效峰值，校验到 0–1 |
| `pacing.developerAcceleration` | `false` | 缩短开发回归等待，不跳过真实交互 |
| `clientState.alphaDowngradeComplete` | `false` | 是否已完成首次 Alpha 降级演出 |
| `clientState.viewDistanceUnlocked` | `false` | 成功诗篇回程后是否已永久解锁视距 |

开发测试时，管理员对自己执行 `/tff debug true`，然后按可重绑的 `M` 打开中文测试工作台。当前四个模块为总览、主线、异象和文件；面板打开期间会实时同步服务端状态，文件栏可查看并调整七份叙事文件的发现、解锁与阅读状态。所有按钮动作都由服务端核对授权、稳定动作 ID、目标和当前上下文。`/tff debug false` 关闭授权。
