# 人工验收清单

本清单面向 `1.0.0-rc.1` 候选包，只列自动化覆盖不到的项目。自动化结果与命令见 [测试与验收](testing.md)，异象/追逐规则见 [异象、终端形态与个人追逐](anomalies-and-pursuits.md)，世界接口精确数值见 [世界接口终局](world-interface.md)。

## 验收前准备

- 使用 Minecraft 1.21.11、Fabric Loader 0.19.3、Fabric API 0.141.4+1.21.11 与 Java 21。
- 安装 `thefourthfrequency-1.0.0-rc.1.jar`，首次验收优先使用新存档。
- 末地结局会给当前存档建立本地隔离标记；正式跑结局前先备份存档。
- 默认关闭开发加速：`pacing.developerAcceleration=false`。
- 需要从中断的结局事务恢复时，以 `-Dthefourthfrequency.safeMode=true` 启动一次。

## 首次安全告知

1. 清除本地安全告知版本文件后进入标题页。
2. 确认 v3 告知在第一次 `TitleScreen` 出现，包含强闪烁/高对比、音量与不可逆存档演出的说明。
3. 确认同一告知版本只显示一次；确认状态写入 `config/thefourthfrequency-safety-notice.version`。
4. 在尚未完成结局时按 F8，确认不会切换 Meta，也不会弹出结局重置框。

## 首启崩坏加载屏

只在新档第一次进世界时出现，约 30 秒。这一屏现在整帧走后处理（`signal_still_*`），所以下面每一条说的都是"作用在画面本身上"，不是"画在画面上"。

1. **文字墙必须一帧铺满整屏**，不得有从中间向外展开的过程。它是一次切换，不是一段过场。
2. **画面不得抖动**：文字行必须笔直、不左右晃、不逐帧位移。整屏应当明显"脏"——颗粒、扫描线、边缘越靠外越明显的红/青分离、亮字周围的光晕、四角压暗——但每一个字自始至终待在原处。这一条是最容易回归的一条：任何让文字动起来的改动都算失败。
3. 失败文字、录制时码、`OBSERVER DETECTED` 都必须**在**这些效果里面（同样带颗粒和色差），而不是浮在上面的干净图层。
4. 中间那条缓慢向上扫过的失踪条是保留的（一次慢扫，不是抖动）；整屏同时只应有这一条。
5. 黑场（dead air）期间画面不得是纯黑：应当看得出是一台还通着电、什么都没收到的显示器——满屏雪花，且雪花是逐像素的，不是几百个可数的小点。
6. 恢复后扫描线与颗粒**不会完全消失**，会停在一个更差的基线上。这是刻意的。

## 新世界与终端

1. 新建生存世界，确认零号站与唯一终端流程可达。站体应完整落地：没有悬空的地板边缘、没有半埋进山坡的墙、屋顶上没有穿出的树干，门外有可直接走下去的门廊。
2. 在站内停到入夜，确认室内与屋顶都不刷敌对生物；确认东侧裂口只能看穿、不能穿行，门是唯一通路。
3. 重复在同一存档上关服再进：已建成的站体不得重建，玩家手动拆掉的方块应保持被拆状态。
4. 终端应只有 `HOME / TOOLS / RECORDS / FILES` 四个玩家页面；网络线协议仍只使用 `SIGNAL / FILES`。
5. 新档第一次打开终端应先播一段开机自检（约 3 秒、六行逐字打出），随后逐个高亮引导点击工具 → 记录 → 文件 → 主页。引导期间按 Esc 与点击其他区域都不生效，且右下角提示必须显示“暂时无法退出”而非“按 Esc 退出”。走完第四步应落在主页，当场看到进度条走满 4/4 与奖励到手。再次打开终端不应再出现引导；已有存档升级后也不应出现。
   - 每一步页面底部应有一条**一行简介**，说明**当前显示的那一页**是干什么的（不是箭头指向的那一页），并以那一页的标签名开头，形如「当前页「主页」：当前目标、推荐工具与最近一条记录」。四步依次介绍主页 → 工具 → 记录 → 文件，与屏幕上真正显示的页面逐帧一致；任何一步出现「箭头指着工具、简介却在讲工具」的错位都算失败。简介只在引导期间出现，引导结束后不得残留、也不得占用任何一页平时的版面。切到英文再走一遍，确认文案完整不被截断。
6. **引导安全阀**：在引导过程中让僵尸打玩家一下，锁定必须立刻解除、能马上按 Esc 退出，且引导进度保留，下次打开从当前步继续。
7. 手持终端与开合演出按下面的《手持终端外观与演出》小节单独逐条核对。
8. 首项任务应为“认识终端”；只有依次实际选择过四个顶部标签后才完成。完成后应立即进入下一项任务并发放右上角显示的奖励；背包空间不足时，剩余奖励掉落在玩家脚边。
   - **完成必须看得见。** 第四个标签落地后，任务卡应把**刚完成的那一项**扣住约 3 秒：进度条补满 4/4、卡片与奖励框转为完成配色、目标行读作「认识终端：点击四个顶部标签 4/4」，右下角写「任务完成」。卡上不应再有一行文字复述发了什么——奖励框本身就画着面包和 ×6。这段停留必须与状态栏的「引导完成」同屏，而不是一前一后。3 秒后卡片才换成下一项任务，进度条从 0 重新爬升（不得出现从满格往回掉的动画）。
   - 关着终端时完成任意后续任务（例如砍够木头），物品栏上方的绿色通知应同时报出**完成了哪一项**和**发了什么**，形如「任务完成：收集木头 · 石斧 ×1」——只报奖励不报缘由算失败，折成两三行也算失败。
9. 六个工具应依次可用：住所、矿物、传送门、天气、导航、要塞。
10. 核对主线目标顺序：

   `12 份任意原木/木板 → 6 份铁样本 → 下界 → 下界要塞 → 8 根烈焰棒 → 返回主世界 → 合成 4 只末影之眼 → 记录 3 次真实投掷 → 接近要塞 → 进入末地 → 击败世界接口`

   “下界要塞”一项需要实地验收：判定要求玩家站进要塞自身的结构部件里，自动化测试造不出一座真实生成的要塞。走进要塞内部应在一秒内完成该任务；站在要塞外的地面、桥下的岩浆海或旁边的地形上都不应完成。

11. 成功获得三颗末影之眼后要塞工具开放；真实末影之眼投掷不足三次时，工具不能提前给出完整定位结论。
12. 完整日记应从一开始常驻 FILES，初始标题全部为动态乱码；每发现一份破损文件，标题恢复约 25%。
13. 四份破损文件只在发现后出现，标题暴露真实名称但固定有 2—3 个字显示为乱码；正文顶部以斜体小字显示“文件内容损坏，已尝试还原”。首次打开分别推进 25%，全部读完才解锁完整日记。
14. 多人中发现状态共享、阅读与完整日记权限独立；解锁完整日记不得生成额外文件或世界结构。带终端真实往返主世界与下界时，`RECORDS` 应记录连续性，完整日记末尾应自行续写。
15. 收到新文件后，顶部 `FILES` 标签应显示未读提示；点击该标签后提示一次性消失，但四份破损文件未逐篇打开时，完整日记仍保持上锁。
16. 逐一查看 7 类文件，确认标题、元信息与正文使用清晰的字号和高对比配色，段间有留白并按正文栏宽度自动换行；长文档右侧显示滚动位置且不会压住文字。
17. 分别在 `FILES`、`RECORDS`、工具详情和导航候选中制造超长内容，确认四处各自滚动、各自裁切，不互相借用滚动位置；`RECORDS` 未读数只统计当前可见的记录条目。
18. 在追逐预警强制打开 `RECORDS` 后关闭终端，再正常打开终端，确认仍回到玩家此前记住的页面，而不是把强制页写成新的默认页。
19. 到达支线信号地点后不打开导航工具，确认接收器直接可调频；保持正确调谐 20 Tick 后才锁定，进度在这段时间内平滑刷新而不是一次跳满。

### 手持终端外观与演出

这一组必须在真实客户端上人工核对：模型的视觉比例、动画手感、FOV 幅度和光敏安全都不是任何自动化测试能替代的。

1. **一体式外壳**：手持时应看到黑铸铁机身、磨损黄铜边条与四角螺丝，左侧一块**横向**大 CRT，右侧自上而下为示波器、圆形罗盘、调谐滑杆、双行 LCD 和底部关闭提示区，示波器右侧另有一枚小型琥珀灯。机身正面应明显是宽扁的（约 2:1），和打开后的面板同比例。**任何角度、任何时刻都不得出现翻盖、折叠、展开或滑动**——设备是封死的。
2. **双手捧持**：应看到两只手从画面下方两侧托住终端。**手不得插进机身**：手腕与手掌应在机身侧壁之外、近面之前，托着而不是穿过。
3. **待机**：终端后仰、屏幕朝上搁在视线下方，低头可瞥见屏幕；带轻微呼吸起伏，幅度必须小到不干扰视线。
4. **打开**：右键后终端抬起、放大、转正到与镜头平行，视野同时略微收窄（幅度不超过约一成），屏幕占满画面后界面才打开。
5. **尺寸**：全程**机身四边都不得超出画面**。请在 4:3 或 16:10 等较窄窗口下复核一次——宽边是最先越界的。
6. **手与终端同步**：抬起过程中终端会放大近一倍而手不会，两只手必须始终贴在机身的下边缘与两侧，**不得随放大向机身中间滑动**，也不得脱开悬空。手和设备画在不同深度，所以这一项只能靠眼睛看画面里对不对齐。
7. **不被遮挡**：在**室内、贴墙、抬头看天花板、低头看地板**四种情况下各看一次，终端都不得整个消失或被切掉一半。这是第一人称手部与世界深度缓冲的固有冲突，设备被拉近相机就是为了压住它。
8. **转向**：快速左右转头、上下甩视角时，终端应有和原版手持物品一致的**轻微滞后**，不得像焊在镜头上一样刚性跟随，也不得抖动或与手错位。
9. **关闭**：退出界面应先看到举在眼前的终端，再平滑落回捧持位置。
10. **边界**：整段演出**不得移动玩家在世界中的位置**；切到第三人称时不得看到任何镜头位移或 FOV 变化，旁观者看到的终端也不受影响。
11. **切入 / 切出**：在物品栏里选中终端，它应从画面下方升入手中；切到别的格子，它应沉下去，新物品照常升起。
12. **状态更新不得冒充换手**：终端**开着**时，收到新信号、发现新文件、完成任务（这些都会改写物品组件）都**不得**让终端掉下去再升起来，也不得重播装备动画。这是最容易回归的一项——请在开着终端时故意触发一次未读，盯住画面。
13. **流畅性**：终端开着时服务端持续推快照，不得让抬起动画重启或卡在半途。开到一半按下关闭、或关到一半再次右键，都应从当前位置连续反向，而不是先弹回去再重来。
14. **副手占用**：副手拿着别的物品时应退回单手持握，且**副手那件物品必须照常显示**，不得被悄悄隐藏。
15. **其它视角**：背包格内仍是原来的平面图标；地面掉落物、展示框与头顶佩戴应显示 3D 外壳且朝向正确。
16. **复位**：动画途中切换手持物品、死亡、切维度、断线或被服务端强制关闭，终端都必须立即复位到待机、视野立刻恢复，而不是卡在半途。
17. **六形态**：逐一核对 0/1 绿、2/3 青、4/5 红；**1、3、5 与各自的偶数邻居必须只差指示灯亮起，外壳不得有任何其他变化**。
18. **界面内的指示灯**：打开界面后，硬件列示波器右侧应有独立的琥珀色指示灯，且不遮挡示波器、罗盘、滑杆、LCD 与关闭提示。无未读时是暗色灯罩加金属边框；有未读信号 / 未读文件 / 未确认导航完成 / 可领取奖励中任意一项时点亮并缓慢呼吸（约 2.4 秒一次），**不得快速闪烁**。阶段变青或变红时该灯仍应保持琥珀色。**灯的亮灭必须与手里物品的形态一致**——手上亮、界面里不亮（或反过来）是失败。

## 异象

1. 检查目录为 19 种可触发异象（含环境静默、时相偏移、计量偏移三项持续型）、阶段为 1—5；`disconnected_base`、`watcher_orbit`、`rework_probe`、`hostile_echo` 只能作为历史/调试名称兼容。
2. 新终端第一次异象应安排在 4–7 分钟；普通间隔按阶段落在 8–14、8–13、7–12、6–10、5–9 分钟。
3. 即使提前获得铁，实际阶段也不得跳过阶段 2；每次升级要求当前阶段至少 20 分钟合格在线时间和 2 次成功异象。
4. 最近三次成功异象不得再次入选；升层后优先观察到新阶段内容。
5. 窗口脉冲、频道接管、桌面在场触发后，20–30 分钟内不得再次出现强接口异象。
6. 多人中个人视觉、声音和输入效果只作用于目标客户端；观察者定向、门扉级联、经历缺口等共享型服务端效果允许附近玩家看见结果。
7. 完成任意一种异象后，终端记录页不得新增对应条目、未读提示或专用记录音效；旧存档已有的异象条目应在同步时清理。
8. 默认按 M 打开 Debug 工作台；它应显示总览、主线、异象、文件四个模块，并在保持打开时实时刷新服务端状态。文件模块应列出七份叙事文件的发现、解锁和阅读状态。服务端仍需对调试动作执行权限和上下文校验。

### 天气工具的天空监测

1. 无异象时打开 `TOOLS` → 天气：四个通道（天顶、地平线、星等、天体相位）应给出稳定读数，地平线走势线平直，页面**完全干净**——没有扫描线、闪烁或故障行。昼夜倒计时全程不得塌成 `——`。
2. 触发 `red_horizon` 后立刻打开该页：地平线通道应在天色明显变红**之前**就开始爬升，走势线可见为爬坡而非跳变。随强度依次出现扫描线 → 滚动带与撕裂行 → 故障行从卡片底部涌入 → 峰值期每约两秒一次的短爆发（刷屏占满卡片 + 花屏色块），每次爆发伴一声故障音。约 40 秒后应完全恢复干净。
3. 爆发最猛时确认四个顶部标签、工具返回按钮与右下角关闭提示**始终可读可点**，撕裂行和花屏不得溢出卡片。把窗口拉到最小和最大各验一次。
4. 触发 `temporal_drift`：昼夜倒计时**必须始终正确**，只有天体相位通道报出偏差；演出不得超过最低一级（只有扫描线与偶发的整行 `——`），全程不得出现撕裂、花屏或故障刷屏。倒计时若出现错误但可信的数字即为不合格。
5. 把天气工具 PIN 到 `HOME`：首页卡片应与工具页说同样的话（同样会塌成 `——`），但不得出现扫描线、刷屏或花屏。
6. 打开其余五个工具与 `HOME`/`RECORDS`/`FILES` 三页，确认异象期间它们**完全无演出**。
7. 故障行必须是仪器语言（无载波、采样被拒、相位基准丢失等），不得出现伪造的异常名或堆栈。

## 个人校正者追逐

1. 分别用挖矿、累计探索 128 格、方块实体/战利品交互、建造和交易建立第一形态活动证明；五条路线均不得要求固定住宅。
2. 第一场前必须先成功完成至少一次异象；安全窗口与镜像槽位确认后，终端提前 10 秒写入绿色“检测到异常信号波动正在接近..”与红色“做好准备...”，actionbar 只显示“终端传来剧烈震动”。打开终端应自动定位记录；Debug 五阶段追逐入口也从该提示开始。
3. 核对五个许可门槛：早期活动、进入下界、烈焰棒并返回、3 次真实投眼、找到要塞。
4. 玩家提前跨过多个门槛时，始终只面对下一实际形态；不得跳形态或连续补发多场追逐。
5. 核对时长与应对：寻声者 60 秒、定向者 75 秒、截断者 85 秒、越界者 95 秒、接口校正者 110 秒。
6. 成功后下一场正式追逐需等待 20–30 分钟；捕获不得死亡或掉落，保持待追逐并在 5 分钟后重试。
7. 捕获、追逐成功和主动断线都必须返回原维度安全位置；来源位置被占用时不得覆盖真实方块。
8. 追逐期间普通异象、主线采样、导航、世界衰败和世界接口服务不得从镜像维度写入真实进度。
9. 核对 10 秒前置时序：4 秒终端阅读、4 秒只降低呈现帧率、2 秒卡死音；WARNING 全程不得出现滤镜、暗角、信号条或纯黑遮罩，之后黑屏应无缝覆盖镜像加载页面和任何资源加载 Overlay。黑屏至少等到目标维度中玩家周围 7×7 区块全部就绪并连续稳定 8 Tick；若始终无法稳定，最迟在 200 Tick（10 秒）硬超时后继续，不得无限卡住。
10. 正式追逐期间底部只常驻“尝试逃离”，其他提示和提示音应延迟到黑屏返程完全结束后；不得出现 bossbar。
11. 在平地持续冲刺并搭建高台或封路，确认追逐校正者会明显追近、快速破障、拆除玩家脚下支撑并垂直追击，且仍能被玩家正常攻击、击杀；再进入无天空光且封闭的矿洞，确认校正者动态减速，回到开阔处后恢复高速。
12. 捕获时确认最后一帧冻结与卡机音持续 3 秒、最大生命减少一颗心，再黑屏返回；技术中断不得扣除生命上限。
12a. 连续触发 4–5 次冻结（预警冻结或捕获结算均可），确认卡机音明显不是同一段：应能分辨出缓冲锁死、高频嗡鸣和衰减成方波这三种不同的卡死方式。同时确认各变体响度一致——抽到任何一个都不应突然变响或变轻。
13. 成功逃离或反杀时确认“尝试逃离”先消失，绿色“你暂时逃离了它...”显示 3 秒、最大生命增加一颗心，再黑屏返回；回到原地点后旧追逐预警应删除，终端新增“用户周围的磁场很不稳定...”记录。
14. 从终端预警开始到返回原维度加载完成前按 ESC，确认“保存并退出/断开连接”按钮禁用并显示“你不能就这样逃走...”；追逐完全结束后按钮恢复。

## 私人镜像与多人隔离

1. 两名玩家同时进入不同形态追逐，确认分别占用不同镜像槽位，互相看不见玩家、校正者、方块修改和掉落物。
2. 第三名玩家在两槽已满时只保留待追逐，不得抢占或传送失败。
3. 入场初始地形应匹配来源位置的 5×5 区块、垂直 ±48 格；水平跑出初始范围后应持续加载新复制区块，不得在 30 格处折返。
4. 极端传送到未复制区块时，只允许短暂停在最近安全位置并暂停追逐倒计时；区块就绪后继续。
5. 镜像挖矿不得获得方块、经验或环境开路耐久损耗；红石、传送门、容器、TNT、床和流体交互应被拒绝或净化。
6. 放置普通建筑方块后结束追逐，确认物品只退款一次；背包已满、断线和重启后仍能由恢复账本交付。
7. 当前版本只允许从主世界和下界开始追逐；末地与模组维度不得正式触发。
8. 在返程前模拟跨维度切换，确认服务端先恢复玩家可见性再传送。再用死亡或管理员传送把玩家移出镜像：会话应释放槽位、结算退款并恢复可见性，不得把玩家强拉回原入口。

## 祭坛与集体仪式

1. 一场个人追逐都未经历过时，向已有 11 只眼的完整要塞门框放入最后一只眼应被拒绝，且末影之眼不得消耗；经历过至少一场后应正常激活。刻意在第一场追逐中被捕获，确认最后一只眼随即可用——捕获不再阻挡终局，但校正者形态仍停留在第一形态。
2. 进入末地后，在原生主岛核对贴地 11×11 祭坛、20 座惰性折跃门与 10 个稳定锚；不应出现大型人工战斗平台。
3. 仪式开始时冻结当前在线的非旁观者名单，支持 1—8 人；名单中每人必须手持自己的有效绑定终端右键共振核心插入。
4. 全员提交前应能撤回或取消；名单变化、重载不确定或事务失败时必须返还终端。
5. 全员提交后应原子提交托管，进入召唤与战斗流程。

## 世界接口战斗

- 最大生命值为 `600 × (1 + 0.5 × (冻结参战人数 - 1))`：1 人 600，2 人 900，3 人 1200，依次每多一人 +300，8 人 2700。血池随人数增长但增速低于队伍的输出增速——多来一个人不是白来，但也不该让同一个 10 分钟计时变得更难打。
- 战斗形态按生命值单向推进：第一形态 `>70%`，第二形态 `>35%`，第三形态 `≤35%`。
- 崩塌计时为 12000 Tick（10 分钟）。只要任一冻结成员在线，计时就继续；全员离线时暂停。
- 存活稳定锚每座每秒回复目标最大生命的 0.02%（10 座合计每秒 0.20%），并投射可见的半径 8 格稳定区；区内玩家所受世界接口伤害降低 20%，区内地形不出现战斗擦伤或缺失材质侵蚀。0 / 5 / 10 枚已拆时，目标承伤应为 60% / 80% / 100%，攻击冷却系数为 1.15 / 1.00 / 0.85，移动速度不变且崩塌计时不变。第一次正伤害玩家攻击应立即拆锚；每次拆除时 HUD 应持续约 3 秒显示金光与“重构↓ / 活性↑”。目标自身不能拆锚。
- **稳定锚外形与破坏演出（需要客户端人工验收）**：柱顶站的应是四向夹具而不是末影水晶——正、侧、后视一致，俯视清楚读成四爪夹紧，四足向内扣住柱顶那一格基岩帽并沿帽边下包，没有底座也没有平台。顶部只有一枚裸露中继核悬在一根极细轴上，四枚校准瓣低于中继核赤道且彼此断开，不组成环、笼或朝上的开口。只有胸腔核心、中继核和关节金缝发光，整具实体不能变成灯笼。拆锚时应看到约 16 Tick 的坍缩，**先炸后收**：中继核当场引爆（爆炸粒子发射器）→ 三圈爆轰波沿基岩帽向外阶梯展开、碎片向外抛 → 一道光柱沿垂直方向射出 → 半径 26 格的冲击环离开柱脚 → 牵引束在中继核收束成亮点后朝 BOSS 方向回抽 → 夹爪折向基岩帽并像素化消散 → 少量紫色微粒散尽。声音应是两层：原版爆炸叠一层压低的锚本嗓。**相机应从锚的位置震一下**，站在被拆的锚旁边比站在岛中心震得更明显（这是本次修正的方向，此前正好相反）。演出结束后柱顶只剩完整基岩帽与黑曜石柱，不得留下火、烟柱、掉落物、残骸或任何方块改动；十座锚短时间连续被拆也不能出现全屏闪烁。
- **牵引束端点**：牵引束应从中继核（锚方块上方 2 格）出发，实时连到移动中的 BOSS 核心，而不是从锚体内部出发，也不是固定竖直光柱。BOSS 上升、下降、绕场时束线角度应随之改变。
- **旧存档迁移**：用 Beta 0.4.0 及更早版本准备过场地的存档进入末地，10 个锚应全部呈现为新实体；已持久化为已拆的锚不得复活，柱顶不应残留末影水晶。竞技场之外的普通末影水晶行为必须完全同原版（可点燃、可被玩家引爆、爆炸伤害与地形破坏照旧）。
- 分别以 0、1—9、10 枚已拆锚完成成功结局，原版终末之诗应选用全数保全、折中、全数拆除三种对应段落，不能一律声称十枚都被毁掉。
- 三个形态的本体都应明显悬在空中，任何时刻都不得有一部分没入地面；召唤下落必须停在空中而不是砸进地里。站在正下方抬头，本体下缘依次约 8 / 14 / 18 格。
- **头部不得穿模到地下（需要客户端人工验收）**：把 BOSS 打到低血量后（结构下垂在低血量时最严重）站在中央头颅正侧方观察，整颗骷髅连同**下颌与牙齿**都必须在地面之上，不能有任何一帧插进末地石。这是本次抬高整体高度的直接目的，三个形态都要看。
- **召唤降临停得更高**：十三秒降临演出结束时，本体应停在比战斗站位更高的位置并悬停一会儿，随后在战斗前几秒里缓慢下压到站位；不应该一落地就已经在战斗高度上。
- **第二、三形态的高空窗口（需要客户端人工验收）**：每约 45 秒，本体会用约 2.5 秒爬升到战斗站位之上 26 格，停留约 8 秒，再用约 2.5 秒下降。爬升起始应先听到一声飞行音与低吼。抬升期间：近战对头、脖子、触手全部够不到，弓/弩/三叉戟仍可命中本体；下降后近战必须重新可用。**总时长不得超过整场战斗的 40%**——用秒表粗测一个 45 秒周期内的抬升时长应在 13 秒左右。第一形态全程不得抬升。
- **形态切换是飞离（需要客户端人工验收）**：第二、三形态切换时，本体应蓄势后快速爬升到看不见的高处，在那里换形态，再落回场地；不应在玩家眼前原地变形。离场与落地各有一次冲击环，落地另有一声吼。这 4 秒内场上没有可攻击目标是预期行为。
- **三颗头会看向目标玩家（需要客户端人工验收）**：站在 BOSS 侧面绕圈跑，三颗头应转向你——中央头转得最多、两侧头跟随较少；本体转身很慢，头应该先于身体转过来。同时确认头转动时颈链**不打结、不互相穿模**，尤其在第二形态和强制驱逐（颈部接近水平）时。
- 站在地面用近战武器攻击**中央头颅与它的脖子**：三个形态都必须能打中，且命中反馈落在看得见的骷髅/颈段上，而不是它们旁边的空气。侧头更高更小，可以够不到。
- **头部判定框要对得上视觉，并且真的打得到**：开启判定箱显示（调试面板），头的方框下沿应当压在**下颌**上而不是悬在下颌上方，顶部仍盖住眉骨；头顶那对角不在框内是预期的。三个形态站在地面挥砍都应能稳定命中（框下沿离地约 1.4 / 0.8 / 0.4 格）。
- **玩家应该追得上 BOSS**：朝本体直线跑过去，它不应该以同样的速度往后退。它只会在离你比站位（本体半径 + 3 格）更远时才靠近，进入之后水平方向就停住，让你自己走完最后一段。
- **头不得"闪现"**：绕着 BOSS 跑，三颗头应当是**连续转过来**的，不能出现静止几帧再跳一下。同时确认它是真的在看你——俯仰上限已经从 30° 放到 60°，正下方也应该能被盯住，而不是永远指在你前方一段距离的空处。
- **吼叫应当是两层**：末影龙的低吼底下压着一层更低的凋零嗓音，形态越大整体越低；不应听成单纯的末影龙叫。
- **一阶段的出手要明显更慢**：两次攻击之间应有 7.5–10 秒的间隔，中间有一段真正安静、够把上一次预警想明白的时间。二、三阶段依次明显加快。
- **高空期间照常出手**：抬升的十几秒里应该仍然挨打（激光、龙息弹、天矛、触手），只是不会再出现抓取投掷——那一招在天花板上必然扑空，已从高空的候选里排除。
- **判定框必须跟着动画走**：在接口正在做动作时（凝视锁定、天矛、触手抽击、强制驱逐、形态切换）挥向看得见的骷髅，仍应命中；反过来，挥向骷髅刚离开的位置应当落空。特别确认头颅在**身体正前方**而不是正后方——这是曾经反掉的一条轴。
- **三颗头不得互相穿模**：三个形态、以及每种行动的整段演出里，两颗侧头之间、侧头与中央颈之间都应看得见空隙；侧颈应向外张开，不得越过中线。第二形态和强制驱逐（颈部被压到接近水平）是最容易复现的两个场景。
- 触手尖端**不会触及地面**（绘制出的末端停在本体下方 4—7 格），因此地面近战打不到触手，这是当前的设定；触手判定只覆盖绘制出的最后一节，用远程或站到高处验证。
- 二、三阶段的技能音效必须与一阶段一样清晰可闻（此前只在 16 格内可闻，而本体核心随形态升到 9 / 16 / 19 格，二三阶段实际是静音的）。逐一确认激光、龙息弹、天矛、抓取、武器扣押、凝视清栏、触手抽击都能在竞技场任意位置听见。
- **长阶段后技能与受击音效不得消失**：在同一阶段持续输出 **3 分钟以上**，尤其要在单人第二阶段反复触发抓取、扣押与清栏；BOSS 必须在强控目标仍处于 600 Tick 保护期时跳过不可用动作、继续使用其他技能，不得停手等待保护期结束。每次真正扣除虚拟血量的命中都应在命中点给出受击声（最快每 4 Tick 一次），粒子仍逐次出现。

  该故障实际上有两层。服务端的无目标强控重选死循环已修复；2026-08-07 01:11 的再次实测中没有任何 scheduler overdue/orphan/refused，服务端仍每 30 秒发出 `110 / 93 / 84` 个提示，其中受击声为 `31 / 35 / 9`，但客户端仍能进入无声状态。客户端峰值仅 `16/247`、滑块数值全部正常，因而新修复直接校正 `SoundEngine.gainBySource[HOSTILE]`，并只恢复 OpenAL 确认处于 `AL_PAUSED` 的 HOSTILE 声源，不触碰正在播放的声源。探针现在还会记录客户端真正收到的 BOSS/受击提示数和最远距离。虚拟血量承伤绕过原版 `LivingEntity` 受击分支，因此受击声仍由成功的伤害事务显式播放。
- **锁定时屏幕中央必须是干净的**：被激光、天矛、抓取、触手或凝视锁定时，紫/红的干扰只应出现在画面边缘（径向遮罩 `CenterClear` 起点在半径 0.55 / 0.42），中间那一块必须完全没有位移、没有色偏、没有方块——那是用来躲的地方。同时确认边缘的干扰是**离散的数字损坏**（整条带被甩开、通道错位、宏块塌陷），而不是均匀的马赛克或模糊。
- **配乐必须一直听得见**：三个阶段各打一段，尤其是齐发龙息弹、天矛落地和激光扫射这些最密集的时刻——BOSS 的音效可以盖过配乐一瞬，但不得让整首曲子从头到尾消失。遭遇战的提示音统一乘 `ENCOUNTER_MIX_TRIM`（0.72），爆炸另按半径压（`BLAST_REACH_BLOCKS` 72），吼叫仍保留 96 格半径，应当仍能从岛的另一头听见。
- **爆破技能必须震到相机（需要客户端人工验收）**：以下每一项在玩家附近发生时都应有可感的相机抖动，且**抖动与爆炸同一瞬间**、不得提前——激光落点扫过身边、天降光束落地、龙息弹起爆（含第三阶段齐发通道同时飞来的多颗）、触手落地、稳定锚被拆、任何冲击环经过。**天矛尤其要确认**：此前抖动比坑早 1.35 秒。距离越远抖动越弱，站在爆点之外应完全不震。
- 八类行动都应能在定向验收中出现：激光扫射、龙息弹、天降光束、武器扣押、抓取抛天、凝视清栏、触手抽击、强制驱逐。
- 只有被扣押武器进入恢复账本；凝视清栏的热栏物品是普通世界掉落物，不得被账本复制或返还。激光、龙息弹、天降光束、抓取抛天与触手抽击才显示目标锁：70% 以上时同时出现锁定音与 `!被锁定!`。武器扣押和凝视清栏是不可规避的剥夺倒计时，只使用下沉低音；强控制不能并发套在同一目标上，同一目标应有 600 Tick 保护期。
- 战斗只显示一套自定义 HUD。世界接口造成的永久伤痕总预算为 8192 格、每 Tick 最多 32 格，并保护返回传送门、黑曜石柱、方块实体、关键 MOD 方块和免疫标签。

### 多人攻击分配（需要 2 人与 4 人各跑一轮完整战斗）

自动化只能证明规则单调、有边界、单人局逐 Tick 不变；下面每一条都必须真机确认。

1. **没有人被连点两次。** 逐次记录被锁定者。只要场上还有别的可选目标，同一名玩家不得连续两次被点名。若出现，先确认另一名玩家当时是否处于 600 Tick 强控免疫或已离开场地 256 格——那是规则允许的回退。
2. **份额大致均衡。** 一整场下来，被点名最多与最少的玩家不应相差三分之一以上。份额不会精确均分，那是刻意的。
3. **第三阶段不会四条预警同时压在一个人身上。** 齐发通道最密的时候观察：排程正在锁定的玩家不应同时被齐发的龙息弹瞄准。
4. **触手抽击的三连击打三个人。** 三名玩家分散站开（互相间隔超过 10 格），确认三次落点不全在最靠前的那个人身上。
5. **强制驱逐不重复踢同一个人。** 4 人局至少触发两次驱逐（冷却 3600 Tick），确认第二次选的是第一次没被踢过的人；集成服务器房主始终不被选中。
6. **本体不再长期停在一个人头顶。** 四人分散站位时，本体应停在队伍之间而不是钉在最近那个人上方；单人时站位、悬停高度与转向速率应与此前完全一致。三个头的注视仍然跟最近的玩家——这一条是**保留**的，不是回归。
7. **节奏是否合适（RC 阶段唯一的开放问题）。** 记录 2 人与 4 人局的通关时间、每人死亡次数和"是否有空档发呆"。间隔按 `1 / (1 + 0.18 × (人数 - 1))`（下限 0.45）收紧、齐发按人数加宽，这两个系数是依据推算选的，没有实测数据支撑。若 4 人局明显过密或仍然过闲，调这两个系数而不是调血池。
8. **抓取投掷不再发假警告。** 多人局里确认：出现全屏锁定边框与锁定音的玩家，一定就是随后被触手抓走的那一个；不得有人收到完整锁定演出后什么都没发生。

## 成功与失败

### 成功

1. 在崩塌达到 100% 前造成致命伤。
2. 核对结算演出的顺序，五拍不得重叠：**9 秒死亡演出**（本体**上升**而非倒下——不得出现翻倒；触手逐条脱落且每条脱落处必须同时有爆发与声响；全身持续冒灰烬且灰烬下落方向与躯体上升方向相反；每约 2 秒一声嘶吼，音量与音高一路走低）→ 本体**离场**（大团灰烬 + 冲击环 + 掐断的低音嘶吼，不得是无声消失）→ 空两秒 → **6 秒召唤演出**（亮点沿轨道跑完一圈、祭坛升起光柱、音效脉冲加密升调）→ 末影龙在**祭坛的光柱里**出现并爆发，随后 70 Tick 螺旋飞出到那条已被点亮的环上 → 龙压向祭坛、用 8 秒把出口撑开 → 出口落地后再用 10 秒**飞回**高空轨道。龙出现时本体必须已经不在场上；开门的粒子与音效应沿龙与祭坛的连线发出，而不是从祭坛自己冒出来。

  **龙的飞行必须全程连续**：从出现、螺旋出场、下降、开门到爬回高空轨道，任何一段都不得出现逐帧的抖动/抽搐（躯体在同一处来回甩、龙头每隔一帧掉头），也不得出现位置或朝向的跳变——尤其盯住**出口落地那一刻**，那里曾经有一次约六十格的瞬移。
3. 核对台词位置：第一句“我见过它看向这里的样子…”在龙还在开门时出现；第二句“剩下的交给我。回去吧…”与出口落地同一刻出现，不得早于出口。
4. 召唤演出期间存盘重启，应从当前结算进度续上而不是重放或跳过；此时不得出现第二条龙。
5. 确认结算后祭坛开放 3×3 返回出口。
6. 进入出口后必须走原版 `showEndCredits → WinScreen → PERFORM_RESPAWN` 流程，只替换本次诗篇、制作人员名单和片尾文本；普通原版结算仍使用原资源。
7. 完成诗篇确认并真正回到主世界后，视距从维度锁定值永久解锁为 16。
8. 标题页应建立结局锁：只禁用单人游戏、多人游戏和 Realms，设置、辅助功能和退出仍可用；本地成功存档显示为“存档已封存”且不可进入。
9. 结算开始后，普通异象、空档补压、衰减与个人追逐应永久停止；成功配乐必须先释放，再恢复资源包，避免回程时重新启动。
10. **打完回到主世界后退出到标题画面，配乐不得中断也不得换成菜单曲**：在主世界等到 `music_game` 起播，然后暂停菜单 →「保存并退出」。存盘画面、标题画面到位的整个过程中，正在播的那一首必须**一直不间断地放下去**（不是淡出后重新起一首，也不是换成 `music_menu`）；标题画面上后续换曲仍应从 `music_game` 里取。随后再进入任意世界，菜单曲淡出与加载静音应恢复常规行为。此项只能靠耳朵，加个 `-Dthefourthfrequency.musicDebug=true` 看 `[music]` 行可辅助确认曲目 ID 没有变。

### 失败

1. 让崩塌先达到 100%；同 Tick 同时发生致命伤时应以失败优先。
2. 普通单人/远程客户端完成固定失败演出后，游戏不应关闭：应回到主世界、整个世界呈现缺失材质，并在屏幕下方反复看到“游戏流程已结束，请返回主菜单”。
3. 已发布 LAN 的集成服务器房主不应关闭服务器；房主回到主世界后只有自己的客户端显示方块、实体和流体为缺失材质，LAN 客人和服务端世界不受影响。
4. 失败同样建立标题页结局锁；本地失败存档显示为“存档已损坏”且不可进入。
5. 失败后从暂停菜单返回主菜单并重新启动客户端，确认退出始终可用，且 Alpha 呈现一直保留到 F8 恢复完成；待处理的 Windows 恢复事务不得提前退休 Alpha。

## F8 重置与存档隔离

1. 结局锁存在时按 F8，确认出现与成功/失败结果对应的恢复/重玩确认文案。
2. 确认后应恢复 MOD 持有的桌面、记事本、窗口和资源包状态，清理客户端演出标记，并正常关闭。
3. 重启后，准确对应的本地结局存档应因 `.thefourthfrequency-corrupted` 隔离标记不可进入；标记记录成功结果时显示“存档已封存”，记录失败结果时显示“存档已损坏”。
4. 核对 `level.dat`、区块和玩家数据没有被 MOD 改写；新游戏必须使用新存档。
